# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A [chezmoi](https://www.chezmoi.io/) source directory for a macOS (Apple Silicon) dev machine. There is no build or test suite: "running" the repo means having chezmoi render it into `$HOME`. The goal is that a fresh Mac can be bootstrapped with a single `chezmoi apply` (with only the unavoidable sudo prompt for Homebrew's install). Many recent commits fix fresh-machine bootstrap bugs, so keep scripts idempotent and non-interactive.

This clone is separate from chezmoi's default source (`~/.local/share/chezmoi`), so pass `--source` when testing from here:

```sh
chezmoi --source . diff                    # preview what would change in $HOME
chezmoi --source . apply --dry-run -v      # dry run, showing scripts that would execute
chezmoi --source . cat ~/.zprofile         # render a single target
chezmoi --source . execute-template < run_onchange_install-mcp-servers.sh.tmpl
```

## chezmoi naming conventions in use

File names encode behavior; they are what chezmoi reads, so renaming changes semantics:

- `dot_` → leading `.`; `private_` → 0600/0700 perms; `executable_` → +x; `.tmpl` → Go template (uses `.chezmoi.homeDir`, `.chezmoi.sourceDir`).
- `symlink_*.tmpl` → the rendered content is the symlink target.
- `modify_*` → a script (Python here) that receives the current live file on stdin and prints the new contents. Used for `~/.claude/settings.json` and Rancher Desktop's `settings.json` so only the keys we own get set and app-generated/machine-specific keys survive. Edit the Python to change those settings, never replace them with a static file.
- `run_once_*` scripts run once per machine (keyed by content hash); if they exit non-zero chezmoi retries them on the next apply, which is used deliberately (e.g. waiting for Docker). `run_onchange_*` re-run whenever their rendered content changes. `before_`/`after_` order them relative to file updates.

## Data-file → script pattern

Package/plugin lists live in plain files at the repo root, excluded from deployment via `.chezmoiignore`, and are consumed by `run_onchange_*.tmpl` scripts that embed `{{ include "<file>" | sha256sum }}` in a comment so editing the list re-triggers the script:

- `Brewfile` → `brew bundle` (each entry has a one-line comment describing it; keep that style)
- `herdr-plugins.txt` → `herdr plugin install`
- `mcp-servers.txt` → `claude mcp add ... -s user` (`name url` per line)
- `Code/Work/dot_envrc` → `direnv allow`

To add a new tool, add it to the appropriate list rather than writing a new install script. Any new top-level non-dotfile must be added to `.chezmoiignore`.

## Cross-file wiring to be aware of

- Scripts run in a non-login bash, so each one bootstraps its own `PATH` (`eval "$(/opt/homebrew/bin/brew shellenv)"`, `~/.rd/bin`, etc.) instead of relying on `.zprofile`.
- Docker comes from Rancher Desktop, started headless by `run_once_after_configure-rancher-desktop.sh`. `DOCKER_HOST` is set in `dot_envrc` (direnv, applied to all of `$HOME`) pointing at `~/.rd/docker.sock`; the Ligatured Hack Nerd Font build script depends on that Docker being up.
- Work vs personal git identity is directory-based via `[includeIf "gitdir:~/Code/github.com/ori-edge/"]` in `dot_gitconfig`. Claude Code's work/personal split is machine-based instead: each Mac logs into one account under the default `~/.claude` config dir, and `dot_claude/` (settings, hooks, theme) is identical across machines via chezmoi.
- The OneDark theme is applied consistently across Ghostty, Neovim, delta/lazygit, glow and Claude Code (`dot_claude/themes/onedark.json`); match it when theming a new tool.
- `dot_claude/hooks/executable_herdr-agent-state.sh` is generated by herdr; don't edit it by hand.
- Neovim config (`dot_config/nvim/private_init.lua`) is a single file using the built-in `vim.pack` plugin manager with `nvim-pack-lock.json` as the lockfile; Neovim itself is managed by `bob`.

## Conventions

- Shell scripts: `#!/bin/bash` + `set -euo pipefail`, guard for idempotency, and explain *why* in comments (existing comments are detailed about non-obvious macOS/tool quirks; keep that standard).
- Commit subjects: recent history uses plain imperative sentences ("Fix Homebrew PATH/ordering bugs…"); commits are GPG-signed.
